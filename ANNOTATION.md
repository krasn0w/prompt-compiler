# Annotation

**English** · [Русский](ANNOTATION.ru.md)

**Prompt Compiler v2.1.0** is a Hermes Agent skill that turns a raw user request into a minimal, clear, directly executable prompt. It is not a prose beautifier and does not inflate requests with a universal template: it preserves the original goal, tone, and constraints; detects material gaps and contradictions; separates input data from instructions; and adds an output contract or observable success criteria only when they help execute the task. If the request is already sufficient, returning it unchanged is a correct result.

The skill was designed with reference to official guidance from Anthropic, OpenAI, Google, and DeepSeek, as well as research on long context, model self-correction, constrained generation, and prompt injection. These materials and the project's priorities support several choices: prefer a clear goal over non-functional claims of expertise; use context and examples only when useful; separate long source material from the instruction; do not demand private chain-of-thought; and add verification when an external signal exists—tests, execution, tools, or ground truth. Vendor-specific settings are applied only when the target model is known; otherwise, the skill emits a portable prompt. The evidence and its limits are documented under [clarity and structure](references/sources.md#src-clear-specific), [long-context placement](references/sources.md#src-long-context-placement), [reasoning models](references/sources.md#src-reasoning-high-level), and [self-correction](references/sources.md#src-self-correction).

By default, Prompt Compiler follows **compile → stop**: it first shows the compiled prompt and briefly reports material changes, but it does not execute the underlying task without an explicit request. This preserves user control and avoids mixing instruction editing with external actions. The skill does not promise a universal improvement across all models and tasks; its rules combine checkable practices with explicit architectural choices, and real gains should be established through project-specific evaluation. See the complete [evidence map](references/sources.md).
